## 1. `mini-cursor2.mjs`：一个简化版 Agent Runtime

这个文件的核心目标是：让模型一边流式输出，一边决定是否调用工具，并在工具调用完成后继续下一轮对话。

整体流程：

```txt
SystemMessage + HumanMessage
  -> model.bindTools(tools)
  -> modelWithTools.stream(messages)
  -> 收集 AIMessageChunk
  -> 拼成完整 AIMessage
  -> 如果有 tool_calls，就执行工具
  -> 把 ToolMessage 放回 history
  -> 进入下一轮循环
```

### `bindTools`

```js
const modelWithTools = model.bindTools(tools);
```

这一步是把 `read_file`、`write_file`、`execute_command`、`list_directory` 这些工具告诉模型。模型不会直接执行工具，它只会返回一个 `tool_calls` 请求，真正执行还是代码里自己做。

### `stream`

```js
const rawStream = await modelWithTools.stream(messages);
```

这里拿到的是流式响应，不是一次性完整结果。后面：

```js
for await (const chunk of rawStream) {
  fullAIMessage = fullAIMessage ? fullAIMessage.concat(chunk) : chunk;
}
```

每个 `chunk` 是一个 `AIMessageChunk`。`concat` 的作用是把这些碎片拼成越来越完整的 `AIMessage`。

第一次：

```js
fullAIMessage = chunk;
```

后面：

```js
fullAIMessage = fullAIMessage.concat(chunk);
```

可以理解成把模型流式生成的文本、工具调用片段、工具参数片段都合并起来。

### `JsonOutputToolsParser`

```js
const toolParser = new JsonOutputToolsParser();
parsedTools = await toolParser.parseResult([{ message: fullAIMessage }]);
```

`parseResult` 不能直接传 `fullAIMessage`，因为它要的不是单个 message，而是 LangChain 的 generation 结构，所以要包一层：

```js
[{ message: fullAIMessage }]
```

也就是：

```js
const generations = [{ message: fullAIMessage }];
await toolParser.parseResult(generations);
```

这段在流式过程中不断尝试解析工具调用。如果 JSON 还没有流完，解析会失败，所以代码用 `try/catch` 忽略错误，继续等后面的 chunk。

这是一种简单可用的 demo 写法，但不是生产最优解。更稳的做法是：

- 流式阶段只做预览。
- 真正执行工具时，等 stream 结束后使用完整的 `fullAIMessage.tool_calls`。
- 不要每个 chunk 都完整 parse 一次 `fullAIMessage`。

### 为什么 `write_file` 可以流式预览

模型调用 `write_file` 时，文件内容在工具参数里：

```js
toolCall.args.content
```

流式输出时，这个 `content` 是逐步增长的，比如：

```txt
第 1 次: "<script>"
第 2 次: "<script>\nlet count = 0;"
第 3 次: "<script>\nlet count = 0;\n</script>"
```

如果每次都打印完整的 `content`，会重复输出已经打印过的内容。所以代码用 `printedLengths` 记录每个工具调用已经打印到哪里：

```js
const previousLength = printedLengths.get(toolCallId);
const newContent = currentContent.slice(previousLength);
process.stdout.write(newContent);
printedLengths.set(toolCallId, currentContent.length);
```

这里是 `slice`，不是 `splice`。

- `slice(previousLength)`：从上次打印的位置开始，截取新增内容。
- `splice` 是数组方法，而且会修改原数组；字符串没有 `splice`。

### 消息历史

流式完成后：

```js
await history.addMessage(fullAIMessage);
```

这一步把完整 AI 回复加入历史。如果 AI 回复里有工具调用：

```js
for (const toolCall of fullAIMessage.tool_calls) {
  const foundTool = tools.find((t) => t.name === toolCall.name);
  const toolResult = await foundTool.invoke(toolCall.args);
  await history.addMessage(
    new ToolMessage({
      content: toolResult,
      tool_call_id: toolCall.id,
    }),
  );
}
```

工具执行结果必须用 `ToolMessage` 放回 history，并且带上 `tool_call_id`，这样模型下一轮才能知道这个工具调用已经有结果了。

## 2. `smart-import.mjs`：结构化抽取并写入 MySQL

这个文件的核心目标是：从一段自然语言文本中抽取好友信息，变成结构化数组，再批量插入 MySQL。

整体流程：

```txt
自然语言文本
  -> zod schema 定义目标结构
  -> model.withStructuredOutput(schema)
  -> 得到 JS 对象数组
  -> mysql2 批量 INSERT
```

### 用 zod 定义结构

```js
const friendSchema = z.object({
  name: z.string().describe('姓名'),
  gender: z.string().describe('性别（男/女）'),
  birth_date: z.string().describe('出生日期，格式：YYYY-MM-DD，如果无法确定具体日期，根据年龄估算'),
  company: z.string().nullable().describe('公司名称，如果没有则返回 null'),
  title: z.string().nullable().describe('职位/头衔，如果没有则返回 null'),
  phone: z.string().nullable().describe('手机号，如果没有则返回 null'),
  wechat: z.string().nullable().describe('微信号，如果没有则返回 null'),
});

const friendsArraySchema = z.array(friendSchema).describe('好友信息数组');
```

这里 zod schema 同时承担两个作用：

1. 告诉模型要输出什么结构。
2. 让 LangChain 把模型输出解析成稳定的 JS 数据。

### `withStructuredOutput`

```js
const structuredModel = model.withStructuredOutput(friendsArraySchema);
```

如果目标只是得到结构化 JSON，`withStructuredOutput` 比手写 parser 更方便。它适合这种场景：

- 信息抽取
- 表单字段生成
- 分类结果
- 固定结构的数据返回

和 `mini-cursor2.mjs` 的区别：

- `mini-cursor2.mjs` 需要工具调用和 agent 循环，所以用 `bindTools`。
- `smart-import.mjs` 只需要结构化结果，所以用 `withStructuredOutput`。

### 调试回调

```js
const result = await structuredModel.invoke(prompt, {
  callbacks: [
    {
      handleLLMStart() {},
      handleLLMNewToken(token) {},
      handleLLMEnd() {},
      handleLLMError(error) {},
    },
  ],
});
```

这里用 callbacks 观察模型调用过程：

- `handleLLMStart`：请求发出。
- `handleLLMNewToken`：收到新 token。
- `handleLLMEnd`：响应结束。
- `handleLLMError`：响应出错。

代码里还加了 `setInterval` 心跳日志，用来判断模型是否还在响应，避免长时间无输出时以为程序卡死。

### 批量插入 MySQL

```js
const insertSql = `
  INSERT INTO friends (
    name,
    gender,
    birth_date,
    company,
    title,
    phone,
    wechat
  ) VALUES ?;
`;

const values = results.map((result) => [
  result.name,
  result.gender,
  result.birth_date || null,
  result.company,
  result.title,
  result.phone,
  result.wechat,
]);

const [insertResult] = await connection.query(insertSql, [values]);
```

这里用 `VALUES ?` 做批量插入。`results` 是模型返回的结构化数组，`values` 把对象数组转换成 MySQL 需要的二维数组。

## 3. 今晚形成的判断

如果只是想要模型返回固定格式的数据：

```js
model.withStructuredOutput(schema)
```

如果需要模型决定调用哪些工具，并且代码要执行这些工具：

```js
model.bindTools(tools)
```

如果要做流式 Agent：

- `chunk` 是当前增量。
- `fullAIMessage` 是累计后的完整消息。
- `concat` 用来合并流式碎片。
- `tool_calls` 最适合在流结束后执行。
- 流式预览可以读取逐步增长的 `toolCall.args.content`。
- 为了避免重复打印，需要用 `slice(previousLength)` 只输出新增部分。
