# 提示词管理

示例项目：

```text
/Users/gephrey/fork-agent/prompt-template-test
```

这一组代码主要是在学 LangChain.js 里的 Prompt Template。核心目的不是“把字符串拼起来”，而是把提示词拆成可复用、可校验、可组合的模块。

## 0. 先记结论

| 场景 | 该用什么 |
| --- | --- |
| 单段字符串模板，有 `{变量}` | `PromptTemplate` |
| 多个提示词模块组合成一个最终提示词 | `PipelinePromptTemplate` |
| 有些变量固定不变，想提前填好 | `.partial()` |
| 要发给 Chat Model，区分 system/human/ai | `ChatPromptTemplate` |
| 要插入历史对话 | `MessagesPlaceholder` |
| 要给模型少量示例 | `FewShotPromptTemplate` |
| few-shot 也是聊天消息格式 | `FewShotChatMessagePromptTemplate` |
| 示例太多，按长度控制 | `LengthBasedExampleSelector` |
| 示例太多，按语义相似度选择 | `SemanticSimilarityExampleSelector` |

## 1. PromptTemplate：最基础的字符串模板

对应文件：

```text
src/prompt-template1.mjs
```

最小用法：

```js
import { PromptTemplate } from '@langchain/core/prompts';

const base = PromptTemplate.fromTemplate(`你好，{name}`);

const result = await base.format({
  name: '张三',
});

console.log(result);
```

输出：

```text
你好，张三
```

重点：

- `{name}` 是占位符。
- `format()` 里必须传入模板里用到的变量。
- `PromptTemplate.fromTemplate()` 会自动从模板里推断变量名。

适合场景：

- 单段 prompt。
- 不需要区分 system/human/ai。
- 最终只想得到一个字符串。

## 2. PipelinePromptTemplate：把多个 Prompt 拼成一个大 Prompt

对应文件：

```text
src/pipeline-prompt-template.mjs
src/pipeline-prompt-template2.mjs
src/pipeline-prompt-template3.mjs
```

思路是：先把大提示词拆成多个小模块，再用最终模板把这些模块装起来。

```js
import {
  PipelinePromptTemplate,
  PromptTemplate,
} from '@langchain/core/prompts';

const personaPrompt = PromptTemplate.fromTemplate(
  `你是一名资深工程团队负责人，写作风格：{tone}。`
);

const contextPrompt = PromptTemplate.fromTemplate(
  `公司：{company_name}
团队：{team_name}`
);

const finalPrompt = PromptTemplate.fromTemplate(
  `{persona_block}

{context_block}

现在开始生成周报。`
);

const pipelinePrompt = new PipelinePromptTemplate({
  pipelinePrompts: [
    { name: 'persona_block', prompt: personaPrompt },
    { name: 'context_block', prompt: contextPrompt },
  ],
  finalPrompt,
});

const result = await pipelinePrompt.format({
  tone: '专业、清晰',
  company_name: '星航科技',
  team_name: 'AI 平台组',
});
```

这里最容易绕的是 `name`：

```js
{ name: 'persona_block', prompt: personaPrompt }
```

意思是：

1. 先执行 `personaPrompt.format(...)`。
2. 把结果塞进一个新变量 `persona_block`。
3. 最终的 `finalPrompt` 可以用 `{persona_block}`。

注意：

- `PipelinePromptTemplate` 通常不需要手写 `inputVariables`，它能从 pipeline 里的各个 prompt 推出来。
- `format()` 时只需要传最底层模块真正需要的变量，例如 `tone`、`company_name`。
- 不需要传 `persona_block`、`context_block`，因为它们是 pipeline 中间生成的变量。

## 3. partial：预填一部分变量

对应文件：

```text
src/partial.mjs
```

如果有些变量很多次调用都一样，可以提前固定。

```js
const pipelineWithPartial = await pipelinePrompt.partial({
  company_name: '星航科技',
  company_values: '「极致、开放、靠谱」的价值观',
  tone: '偏正式但不僵硬',
});

const result = await pipelineWithPartial.format({
  team_name: 'AI 平台组',
  manager_name: '刘东',
  week_range: '2025-02-10 ~ 2025-02-16',
  team_goal: '上线周报 Agent 到内部试用环境，并收集反馈。',
  dev_activities: '- 小明：完成 Git/Jira 集成封装',
});
```

理解方式：

- `partial()` 不是马上生成最终 prompt。
- 它返回一个“已经填了一部分变量的新模板”。
- 后面 `format()` 的时候，只需要补剩下的变量。

适合场景：

- 公司名、价值观、人设、输出格式长期固定。
- 每次只变任务内容、时间范围、开发活动。

## 4. ChatPromptTemplate：聊天消息格式的 Prompt

对应文件：

```text
src/chat-prompt-template.mjs
src/chat-prompt-template2.mjs
```

Chat Model 更推荐喂 messages，而不是一整段字符串。

```js
import { ChatPromptTemplate } from '@langchain/core/prompts';

const chatPrompt = ChatPromptTemplate.fromMessages([
  ['system', '你是一名{role}。'],
  ['human', '请根据下面内容生成周报：{input}'],
]);

const messages = await chatPrompt.formatMessages({
  role: '资深技术负责人',
  input: '本周完成订单模块重构。',
});
```

`fromMessages()` 里常见角色：

- `system`：模型角色、规则、风格。
- `human`：用户输入。
- `ai`：示例里的模型回复，常用于 few-shot。
- `tool`：工具调用相关消息，普通 prompt 入门阶段先不用管。

也可以写成更明确的模板类：

```js
import {
  ChatPromptTemplate,
  SystemMessagePromptTemplate,
  HumanMessagePromptTemplate,
} from '@langchain/core/prompts';

const systemTemplate = SystemMessagePromptTemplate.fromTemplate(
  `你是一名资深工程团队负责人，写作风格：{tone}。`
);

const humanTemplate = HumanMessagePromptTemplate.fromTemplate(
  `本周信息如下：{dev_activities}`
);

const prompt = ChatPromptTemplate.fromMessages([
  systemTemplate,
  humanTemplate,
]);
```

什么时候用 ChatPromptTemplate：

- 你要调用 `ChatOpenAI`。
- 你想清楚地区分系统规则和用户输入。
- 你要插入历史对话或 few-shot 聊天示例。

## 5. MessagesPlaceholder：插入历史对话

对应文件：

```text
src/messages-placeholder.mjs
```

这个是会话型 prompt 的关键：中间留一个坑，运行时把历史消息插进去。

```js
import {
  ChatPromptTemplate,
  MessagesPlaceholder,
} from '@langchain/core/prompts';

const chatPromptWithHistory = ChatPromptTemplate.fromMessages([
  ['system', '你是一名资深工程效率顾问。'],
  new MessagesPlaceholder('history'),
  ['human', '这是用户本轮的新问题：{current_input}'],
]);

const messages = await chatPromptWithHistory.formatPromptValue({
  history: [
    { role: 'human', content: '我们在做周报自动生成工具。' },
    { role: 'ai', content: '可以先拆 Prompt 模块。' },
  ],
  current_input: '现在想优化多人协同编辑流程。',
});
```

重点：

- `new MessagesPlaceholder('history')` 里的 `history` 是变量名。
- `formatPromptValue()` 时必须传 `history`。
- `history` 不是字符串，而是一组消息。
- 适合多轮对话、Agent 记忆、聊天上下文拼接。

## 6. FewShotPromptTemplate：带少量示例的字符串 Prompt

对应文件：

```text
src/fewshot-prompt-template.mjs
```

Few-shot 的意思是：给模型看几条例子，让它模仿结构和风格。

```js
import {
  FewShotPromptTemplate,
  PromptTemplate,
} from '@langchain/core/prompts';

const examplePrompt = PromptTemplate.fromTemplate(
  `用户输入：{user_requirement}
模型示例输出：
{report_snippet}
---`
);

const examples = [
  {
    user_requirement: '重点突出稳定性治理。',
    report_snippet: '- 处理线上故障，补充告警，降低风险。',
  },
];

const fewShotPrompt = new FewShotPromptTemplate({
  examples,
  examplePrompt,
  prefix: '下面是几条周报示例：',
  suffix: '请参考上面的风格，写一份新的周报。',
  inputVariables: [],
});

const prompt = await fewShotPrompt.format({});
```

几个字段的作用：

| 字段 | 作用 |
| --- | --- |
| `examples` | 示例数据数组 |
| `examplePrompt` | 单条示例怎么格式化 |
| `prefix` | 所有示例前面的说明 |
| `suffix` | 所有示例后面的最终任务 |
| `inputVariables` | suffix/prefix 里运行时要填的变量 |

注意 `inputVariables`：

- `FewShotPromptTemplate` 这里要写。
- 如果 `prefix/suffix` 里没有 `{变量}`，写 `inputVariables: []`。
- 如果 `suffix` 里有 `{current_scenario}`，就写 `inputVariables: ['current_scenario']`。
- `examplePrompt` 里的变量不算这里的 `inputVariables`，它们来自 `examples` 每条数据。

## 7. FewShotChatMessagePromptTemplate：聊天形式的 few-shot

对应文件：

```text
src/fewshot-chat-prompt-template.mjs
```

如果最终要给 Chat Model，few-shot 示例也可以做成 human/ai 消息对。

```js
import {
  ChatPromptTemplate,
  FewShotChatMessagePromptTemplate,
} from '@langchain/core/prompts';

const fewShotExamples = new FewShotChatMessagePromptTemplate({
  examplePrompt: ChatPromptTemplate.fromMessages([
    ['human', '本周工作：{input}'],
    ['ai', '{output}'],
  ]),
  examples: [
    {
      input: '完成支付稳定性治理。',
      output: '- 完成故障处置、告警优化和应急演练。',
    },
  ],
  inputVariables: [],
});

const chatPrompt = ChatPromptTemplate.fromMessages([
  ['system', '你是一名资深技术负责人。'],
  fewShotExamples,
  ['human', '这是我本周的实际工作：{current_work}'],
]);
```

理解：

- `FewShotPromptTemplate` 生成字符串。
- `FewShotChatMessagePromptTemplate` 生成聊天消息片段。
- 它可以作为 `ChatPromptTemplate.fromMessages([...])` 里面的一项。

## 8. ExampleSelector：示例太多时自动挑

few-shot 示例少的时候可以直接写 `examples`。示例多了以后，不应该每次都塞给模型，要挑最合适的。

### 8.1 LengthBasedExampleSelector：按长度挑

对应文件：

```text
src/example-selector1.mjs
```

用途：控制 prompt 长度，避免示例太多太长。

```js
import { LengthBasedExampleSelector } from '@langchain/core/example_selectors';

const exampleSelector = await LengthBasedExampleSelector.fromExamples(examples, {
  examplePrompt,
  maxLength: 700,
  getTextLength: (text) => text.length,
});

const fewShotPrompt = new FewShotPromptTemplate({
  prefix: '下面是一些周报片段示例：',
  examplePrompt,
  exampleSelector,
  suffix:
    '场景描述：{current_requirement}\n' +
    '请输出一份 Markdown 周报草稿。',
  inputVariables: ['current_requirement'],
});
```

重点：

- `maxLength` 控制选出来的示例总长度。
- `getTextLength` 可以先用字符长度，真实项目里最好用 token 估算。
- `examples` 和 `exampleSelector` 二选一，不能同时传给 `FewShotPromptTemplate`。

### 8.2 SemanticSimilarityExampleSelector：按语义相似度挑

对应文件：

```text
src/example-selector2.mjs
src/weekly-report-examples-writer-milvus.mjs
```

用途：当前输入是什么场景，就从向量库里找语义最接近的几个示例。

当前项目里的链路：

1. `weekly-report-examples-writer-milvus.mjs` 把周报示例写入 Milvus。
2. 每条示例会用 Embeddings 转成向量。
3. `example-selector2.mjs` 连接已有 Milvus collection。
4. `SemanticSimilarityExampleSelector` 根据当前场景查最相近的 `k` 条。
5. `FewShotPromptTemplate` 把查到的示例拼进 prompt。

核心代码：

```js
const vectorStore = await Milvus.fromExistingCollection(embeddings, {
  collectionName: COLLECTION_NAME,
  clientConfig: {
    address: milvusAddress,
  },
});

const exampleSelector = new SemanticSimilarityExampleSelector({
  vectorStore,
  k: 2,
});

const fewShotPrompt = new FewShotPromptTemplate({
  examplePrompt,
  exampleSelector,
  prefix: '下面是一些不同类型的周报示例：',
  suffix:
    '场景描述：{current_scenario}\n' +
    '请输出一份 Markdown 周报草稿。',
  inputVariables: ['current_scenario'],
});
```

重点：

- 语义选择依赖 Embeddings 和向量库。
- `k: 2` 表示每次选 2 条最相近示例。
- 当前场景变量 `current_scenario` 会传给 selector，用来做相似度检索。
- Milvus 里的字段名要和 `examplePrompt` 使用的变量名对上，比如 `{scenario}`、`{report_snippet}`。

## 9. format / formatMessages / formatPromptValue 的区别

| 方法 | 返回什么 | 常见对象 |
| --- | --- | --- |
| `format()` | 字符串 | `PromptTemplate`、`FewShotPromptTemplate`、`PipelinePromptTemplate` |
| `formatMessages()` | message 数组 | `ChatPromptTemplate` |
| `formatPromptValue()` | PromptValue 对象，可转字符串或消息 | `ChatPromptTemplate`、带 history 的场景 |

简单记：

- 要字符串：`format()`。
- 要喂给 Chat Model 的 messages：`formatMessages()`。
- 不确定后面要字符串还是 messages：`formatPromptValue()`。

## 10. inputVariables 到底什么时候要写

这是最容易烦的点。

### PromptTemplate.fromTemplate

一般不用写：

```js
const prompt = PromptTemplate.fromTemplate('你好，{name}');
```

它能自动推断 `name`。

### PipelinePromptTemplate

一般不用写：

```js
const pipeline = new PipelinePromptTemplate({
  pipelinePrompts: [...],
  finalPrompt,
});
```

它会从子 prompt 和 final prompt 推断。

### FewShotPromptTemplate

通常要写：

```js
const prompt = new FewShotPromptTemplate({
  examples,
  examplePrompt,
  prefix: '...',
  suffix: '场景：{current_scenario}',
  inputVariables: ['current_scenario'],
});
```

如果没有运行时变量：

```js
inputVariables: []
```

### FewShotChatMessagePromptTemplate

也通常要写：

```js
const fewShotExamples = new FewShotChatMessagePromptTemplate({
  examplePrompt,
  examples,
  inputVariables: [],
});
```

这里的 `inputVariables: []` 表示“这段 few-shot 示例本身不依赖外部运行时变量”。

## 11. 常见坑

1. `examples` 和 `exampleSelector` 不能同时传。

```js
new FewShotPromptTemplate({
  examples,
  exampleSelector, // 不行
});
```

二选一。

2. `FewShotPromptTemplate` 的 `inputVariables` 看的是 `prefix/suffix`，不是 `examplePrompt`。

```js
const examplePrompt = PromptTemplate.fromTemplate('{input} -> {output}');

new FewShotPromptTemplate({
  examplePrompt,
  examples,
  suffix: '当前输入：{current_input}',
  inputVariables: ['current_input'],
});
```

`input`、`output` 来自 examples；`current_input` 来自运行时 format。

3. `MessagesPlaceholder` 要传消息数组，不是普通字符串。

```js
history: [
  { role: 'human', content: '...' },
  { role: 'ai', content: '...' },
]
```

4. Pipeline 里的中间变量不要手动传。

`persona_block`、`context_block` 是 pipeline 生成的，不是用户输入。

5. Chat 模型优先用 messages。

能用：

```js
await model.invoke(messages);
```

就不要先把所有东西硬拼成一整段字符串。

## 12. 最后整理一遍心智模型

Prompt 管理可以按层次理解：

```text
PromptTemplate
  最小单位：一段带变量的字符串

PipelinePromptTemplate
  组合单位：把多个 PromptTemplate 拼成一个大任务

ChatPromptTemplate
  消息单位：把提示词拆成 system/human/ai

MessagesPlaceholder
  历史单位：把已有对话插到消息数组中

FewShotPromptTemplate
  示例单位：把 examples 格式化后插入 prompt

ExampleSelector
  筛选单位：示例多了以后，按长度或语义挑一部分
```

一句话版本：

> PromptTemplate 管一段话，Pipeline 管模块组合，ChatPromptTemplate 管消息结构，FewShot 管示例，ExampleSelector 管从一堆示例里挑哪些给模型看。
